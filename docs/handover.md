# 管理の引き継ぎ手順

お香芽の業務アプリは、林がずっと管理する前提で作っています（スプシ・GAS・GitHubはすべて林のアカウント）。
この文書は、いつか誰かに管理を引き継ぐ日のためのものです。**仕組みを変えたら、この文書も直してください。**

最終更新：2026-10-14（土台を作った時点）

---

## 1. 今の仕組み

| もの | 場所 | 持ち主 | ほかの人 |
|---|---|---|---|
| スプシ「お香芽 業務データ」 | 林のGoogleドライブ | 林 | オーナー・店長：編集者として共有。ただし記録のタブは保護されていて、見るだけ |
| GAS「お香芽 業務アプリ」 | スプシに付いている（拡張機能 → Apps Script） | 林（スプシと同じ） | — |
| GASのデプロイ（ウェブアプリ） | 次のユーザーとして実行：林／アクセス：全員 | 林 | — |
| 画面（アプリ） | GitHub `peruperu483/okame` の `v2/`（GitHub Pagesで公開） | 林 | — |
| GASのコードの控え | 同じリポジトリの `gas/Code.gs` | 林 | — |
| タブレット | 店 | 店 | 共有トークンを1回入れて使う |

### データの流れ
タブレットのアプリ → 端末に保存（送信待ち）→ GASのウェブアプリ → スプシ
- GASは林の権限で動くので、保護されたタブにも書ける
- オーナー・店長がスプシで記録を直接書き換えることはできない（直すのはアプリから）

### 秘密情報の置き場所（リポジトリには置かない）
GASの **プロジェクトの設定 → スクリプト プロパティ**
| キー | 中身 |
|---|---|
| `SHARED_TOKEN` | 共有トークン。タブレットが最初に入れるもの |
| `PIN_SALT`・`PIN_HASH` | 店長の暗証番号（元の番号は残っていない） |

### 林がふだんしていること
- GASを直すとき：Code.gsを貼り替え → 保存 →（表や列を足したら setup を実行）→ デプロイを管理 → 鉛筆 → 新バージョン → デプロイ（[セットアップ手順.md](セットアップ手順.md) の「あとでGASを直すとき」）
- 画面を直すとき：`v2/` を直し、`v2/sw.js` の `VERSION` を上げて GitHub に push
- GASのURLが変わったとき：`v2/config.js` の `GAS_URL` を直して push

## 2. 引き継ぐ手順

引き継ぐ相手を「新しい管理者」と書きます。月の締め（月次の確認）が終わった直後、林と新しい管理者が同時に作業できる日に行います（1時間ほど）。

### 2-1. 事前に
- [ ] 新しい管理者のGoogleアカウントとGitHubアカウントを確かめる
- [ ] 2人とも個人のGoogleアカウントか確かめる（組織のGoogle Workspaceどうしだと、持ち主を譲れません。その場合は新しい管理者のアカウントでスプシを作り直し、記録を写します）
- [ ] タブレットの「送信待ち」が0件であることを確かめる（**途中でアプリのURLが変わると、送信待ちが残ったまま取り出せなくなります**）

### 2-2. スプシとGASを譲る
1. スプシの **共有** で、新しい管理者を **編集者** に追加
2. 新しい管理者の右の「編集者 ▼」→ **オーナー権限の譲渡** → 新しい管理者が承諾
   - GASも一緒に新しい管理者のものになる。スクリプトプロパティ（共有トークン・暗証番号）はそのまま
3. **新しい管理者のアカウントで** スプシを開き、拡張機能 → Apps Script → 関数 **setup** を実行して権限を承認
   - タブの保護の「直接書き換えられる人」が新しい管理者に切り替わる（setupは実行した人だけを残す）
   - 記録・暗証番号・共有トークンは変わらない

### 2-3. デプロイを作り直す
「次のユーザーとして実行：自分」は**デプロイした人**の権限で動きます。林のデプロイのままだと林の権限で動き続け、林が外れると止まります。
1. 新しい管理者のアカウントで **デプロイ → 新しいデプロイ** → ウェブアプリ（実行：自分／アクセス：全員）
2. 新しいURLの末尾に `?action=ping` を付けて開き、`"status":"ok"` を確かめる
3. `v2/config.js` の `GAS_URL` を新しいURLにして push
4. タブレットでアプリを1〜2回開き直す（新しいURLに切り替わる）。来客を1件テストで入れ、スプシに入るか確かめてから、そのテストの記録を削除
5. 林のデプロイを **デプロイを管理 → アーカイブ**

### 2-4. GitHubを譲る
二通りあります。
- **A. 林のリポジトリのまま、新しい管理者を共同編集者にする**（おすすめ。アプリのURLが変わらない）
  - リポジトリの Settings → Collaborators → 新しい管理者を追加
- **B. リポジトリごと譲る**（Settings → Transfer）
  - アプリのURLが `新しい管理者.github.io/okame/v2/` に変わる
  - タブレットでは別のアプリ扱いになるので、**送信待ちが0件なのを確かめてから**、新しいURLをホーム画面に追加し直し、共有トークンを入れ直す。古いアイコンは消す

### 2-5. そのほか
- [ ] トリガー（使うようになっていたら）：トリガーは作った人のものとして動く。新しい管理者で作り直し、林のものを削除（Apps Scriptの左の時計のアイコン）
- [ ] レシート画像のドライブのフォルダ（仕入れの読み取りを入れていたら）：オーナー権限を譲る
- [ ] Claude APIのキー（入れていたら）：新しい管理者のキーに替え、スクリプトプロパティを書き換える。林のキーは無効にする
- [ ] 林の権限：しばらく編集者のまま残し、落ち着いたら外す

### 2-6. 終わったあとの確認
- [ ] `?action=ping` で `"status":"ok"`（新しいURL）
- [ ] タブレットで来客を入れると、スプシに入る
- [ ] タブレットで設定を開ける（暗証番号はそのまま）
- [ ] オーナー・店長がスプシの記録のタブを直接書き換えようとすると止められる
- [ ] 林の古いデプロイがアーカイブされている
- [ ] この文書の「1. 今の仕組み」を新しい管理者の名前に直した
